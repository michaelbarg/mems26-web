**Which series is wrong — the bars.** The trades' own prices are confirmed by the broker.
`pnl_sierra` is not our arithmetic: `backend/v9/services/sierra_pnl_reconcile.py` reads entry price,

- **#439** 07-21 18:05 SHORT 2c: −7.75 × 2 × $5 = −$77.50 = `pnl_sierra` −77.50.

At the same timestamps the bar table says something else entirely. 07-23 18:45: broker fill 7425.25;
stored bar `[o 7449.75, h 7449.75, l 7440.25, c 7440.25]` — **15 to 24 points away.**
The **S2 detector's own setup price** at that stamp is also 7425.25 (Q15), as is the shadow entry.
So the detector, the shadow book, the live book and the broker all agree; only the bar row disagrees.

**No lag correction rescues it.** On 07-23 the divergence is zero until 18:20, then the bars run
~25 points *above* the traded market (18:25–19:00), re-converge at 19:10 (detector 7444.25 inside bar
`[7444.25, 7448.75]`), then invert — at 20:25 the detector saw 7450.50 while the bar reads
`[7431.00, 7435.50]`. Direction and magnitude both change within one session. This is a
stalled/re-synchronising export, not an offset. (Related, already on record: T-265 frozen RTH
`5min.json`; the root fix logged 2026-07-29 as "bars = 5h skew" — **after** this entire slice.)

**Consequence:** every column-1 fact Michael asked for — gap, IB, range extension, where value sat,
session extremes — is bar-derived. Where the bars are not the market, those facts are not facts.

### 0.3 Admissibility rule, applied

A window carries a **doctrine call** only if (a) every price point inside it falls in its own bar, and
(b) every bar-derived input the start-of-window call depends on — including the **prior session's RTH**,
which supplies prior close / prior range / prior value — comes from admissible windows.

Per-window bar check (Q17): **24 of 39 windows admissible**, 15 not.
After propagating the prior-session dependency:

| tier | sessions | windows |
|---|---|---|
| **A — doctrine call made** | 07-07, 07-08, 07-09, 07-10, 07-13, 07-14 (all 3 windows each) + **07-15 W1** (prior session 07-14 is clean, own window 6/6 clean) | **19** |
| **B — UNDETERMINED** | 07-15 W2/W3 · 07-17 all · 07-20 all · 07-21 all · 07-22 all · 07-23 all · 07-24 all | **20** |

> **07-21 / 07-22 / 07-23 / 07-24 W1 are individually clean (2/2, 2/2, 8/8, 6/6) but their prior
> session is not**, so the Dalton opening rule — which is entirely about location versus yesterday's
> value and range (pp.74, 84, 88) — has no admissible input. They are marked UNDETERMINED rather
> than answered from a contaminated prior day.

**Money is reported for all 39 windows.** Broker P&L does not depend on the bar table.

### 0.5 Anti-hindsight rule used for the Dalton column

The call is written from information available **at 16:30 / 17:30 / 21:00** and nothing later.
Where the doctrine's instruction depends on the opening type (which is not knowable at 16:30:00),
the call is stated as a plan and the branch is resolved **only from bars 1–3 (16:30–16:45)** —
information a trader holds before the earliest realistic entry in that window. The Open-Drive test
used is mechanical: bar 1 closes in the top/bottom 25% of its range **and** bars 2–3 never trade back
through bar 1's open (p.63). No window's call uses a bar later than the moment of the call.
Outcomes are read only after the call is written.
