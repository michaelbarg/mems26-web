### שני מצבי-שקר, שניהם הוכחו ב-DB

1. **סטופ הוזז מעל הכניסה (SMART_BE/טרייל) ⇒ 0% תמידי.** עסקת-אמת **#942**
   ‏(LONG ‏4c, ‏entry ‏7660.25): ‏`SMART_BE 7652.75→7660.50` ב-17:30:32
   ‏(v9_trade_management_log) — הסטופ **0.25 מעל** הכניסה. מ-17:30 עד ה-STOP_HIT
   ב-17:58:38 — **28 דקות** — המונה `(7660.25 − mid)/0.25·100` שלילי-ענק ⇒ קלאמפ
   ‎−100 ⇒ המסך הציג **"מהדרך לסטופ 0%"** גם כשהמחיר נשק לסטופ. במקביל
   `next_target_pct` ליעד ‏t2=7669 הראה ‎+35% סביב ‏mid≈7663.3 — בדיוק צמד-המספרים
   מהתלונה ("0% / ‎+35%").
2. **סטופ = כניסה בדיוק ⇒ השורה נעלמת.** עסקת-אמת **#881** (בת-SCALE_IN):
   ‏`SMART_BE →7682.50` = ‏entry שלה בדיוק ⇒ `abs(_entry−_stop)==0` ⇒ התנאי בשורה
   221 נכשל ⇒ אין `stop_pct` בכלל — דווקא כשהמידע "כמה רחוק הסטופ" הכי חשוב.

### הנוסחה הנכונה (מפרט)

עוגן = `entry_avg` (סעיף A) וסטופ = הסטופ הנוכחי מה-DB:

```python
risk_band = _mul * (entry_avg - stop)          # >0 ⇒ הסטופ בצד-ההפסד
dist_stop_pts = _mul * (mid - stop)            # מרחק אמיתי לסטופ, תמיד
if risk_band > 0:      # סטופ עדיין מתחת/מעל הכניסה — אחוז-סיכון תקף
    stop_pct = clamp(_mul * (entry_avg - mid) / risk_band * 100, -100, 100)
else:                  # BE או טוב-ממנו — אחוז-מהכניסה חסר-משמעות
    stop_pct = None
    stop_state = "BE+" ; locked_pts = _mul * (stop - entry_avg)   # ≥0
```

- **תמיד** לשלוח `dist_stop_pts` ולהציגו ("‎1.2 נק׳ מהסטופ") — זה המספר שמציל.
- כש-`stop_state="BE+"`: להציג "סטופ מובטח ‎+X נק׳ · Y נק׳ מהסטופ" במקום `0%`.
- בצד-JS (שני הדפים): להסיר את `Math.max(t.stop_pct,0)` — שלילי אמיתי (מחיר בצד-הרווח
  כשהסטופ עוד בצד-ההפסד) יוצג `0%` רק אם `dist_stop_pts` מוצג לידו; עדיף
  `t.stop_pct==null ⇒ שורת-BE`.
- ‏`quality->>'initial_stop'` קיים (25/55 עסקאות 21-יום) — אופציונלי להציג גם
  "% מהסיכון המקורי" כשקיים; לא חובה ללילה.
