# S1 CVD Live — Opening Classification Replacement

**Date:** 2026-05-31  
**Agent:** Claude Code (Opus 4.6)  
**Commit:** `216520d`  
**Flag:** `S1_CVD_OPENING` — when True, CVD replaces price-based opening type

---

## Change Summary

**Before:** `detect_opening_type_cvd()` computed CVD label as shadow only. Price-based `detect_opening_type()` was always the live result regardless of flag.

**After:** When `S1_CVD_OPENING=True` AND footprint deltas available AND CVD produces a classification (DRIVE/AUCTION/REJECTION_REVERSE):
- CVD label **becomes the live `opening_type`**
- Feeds `DECISION_MATRIX` → `day_type` → playbook
- `shadow["cvd_is_live"] = True` for audit trail

**Fallback chain:**
1. Flag OFF → price-based (original, unchanged)
2. Flag ON + no deltas → price-based (fallback)
3. Flag ON + deltas but CVD=UNKNOWN → price-based (fallback)
4. Flag ON + deltas + CVD classified → **CVD is live**

| UNKNOWN | (fallback to price-based) | — |

Direction: derived from `net_cvd` sign (UP if positive, DOWN if negative).

## Impact Analysis

### What changes in SHADOW when flag is ON:

| Component | Before (flag OFF) | After (flag ON + CVD) |
|-----------|-------------------|----------------------|
| `opening_type` | Price-based only | CVD-based when available |
| `day_type` (via DECISION_MATRIX) | Determined by price-based opening | Determined by CVD-based opening |
| Playbook selection | Based on price-opening | Based on CVD-opening |
| Pattern firing | Gated by day_type | Gated by (possibly different) day_type |

### What does NOT change:

- Order routing: still SHADOW only, no DEMO/LIVE orders
- Risk/sizing: unchanged
- Polling intervals: unchanged
- k-values: priors locked (no calibration)
- Price-based `detect_opening_type()`: still runs (result stored in `shadow["original_label"]`)

## Activation

**Current state:** `S1_CVD_OPENING=False` (flag OFF). To activate:

```bash
export S1_CVD_OPENING=True
```

This will cause:
- Opening type to be CVD-sourced when footprint deltas are available
- Different `day_type` classifications when CVD disagrees with price action
- Different playbook selection / pattern gating
- All still in SHADOW mode — no real orders

**Prerequisite for activation:**
- `v9_bars_footprint.delta` being ingested (bridge footprint stream active)
- Session-reset-aware delta computation upstream

## No Code Path to Orders

Verified: `detect_opening_type_cvd` → `state_machine._stage_a2` → `DECISION_MATRIX` → `day_type` → `playbook`. The playbook **does not route to gateway** — it produces classification/strategy metadata only. Trade firing is via `setup_emitter` → `gateway.route_setup()`, which is a separate code path gated by S2/S3/S4 pattern detection, not by S1 day_type directly.
