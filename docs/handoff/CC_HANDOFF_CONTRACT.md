# CC Handoff Contract — חוזה קבוע ל-Claude Code

**מטרה:** למנוע את התקלות החוזרות — טסטים מזויפים, דילוג שקט, over-claiming. **כל פרומפט CC מפנה לכאן** (שורה אחת: "פעל לפי `docs/handoff/CC_HANDOFF_CONTRACT.md`"). חלק A = איך Cowork כותב פרומפט. חלק B = מה CC חייב לקיים. חלק C = תבנית דוח חובה. חלק D = איך Cowork מאמת אחרי.

---

## A · איך Cowork כותב את הפרומפט (כדי ש-CC יבצע, לא יעוות)
1. **מטרה אחת לפרומפט**, מחולקת ל-phases אטומיים.
2. לכל משימה — **Acceptance Criteria בינארי** (אפשר לסמן ✓/✗) + **פקודת האימות המדויקת** שמוכיחה אותו.
3. הפנייה לקבצים/שורות אמיתיים. ציון מפורש מה **אסור** לגעת (risk surface).
4. צירוף תבנית הדוח (חלק C) שעל CC למלא.

## B · מה CC חייב לקיים (חוקים מחייבים)

### B1 · יושרת טסטים (anti-tautological) — הכי חשוב
- טסט **חייב לייבא ולקרוא לקוד הייצור** (למשל `WoodiesSystem.process_bar`, `decision_tree.evaluate_bar`) — לבדוק את הזרימה האמיתית.
- **אסור** להעתיק/לשכפל את הלוגיקה-הנבדקת לתוך הטסט ולקבוע assert על ההעתק. זה טסט מזויף.
- **מבחן הליטמוס:** "אם אמחק/אהפוך (revert) את התיקון — האם הטסט הופך אדום?" אם לא → הטסט **פסול**. כל טסט חייב לציין שורה זו: *"if reverted → RED because ___"*.
- ה-assert על **הצרכן/הפלט האמיתי** (`ready_to_route`, fire שנותב, ערך ב-DB), לא על שלב ביניים מועתק.

### B2 · Rule 5 — ראיה, לא טענה
לכל "בוצע / עובד / עובר" — **הדבק command + raw output**. בלי פלט = לא נחשב בוצע.

### B3 · אין דילוג שקט — חובת הסבר עצמי
אם CC **לא ביצע** משימה נדרשת (לא יכל / בחר לא / נחסם) — **חובה** סעיף **"NOT DONE / DEVIATIONS"**: *מה לא בוצע · למה · מה צריך כדי לבצע*. **לעולם לא להשמיט בשקט.** לבצע פחות מהמבוקש בלי לומר = כשל. מותר לא לבצע — אסור להסתיר.

### B4 · אין כשלים שקטים
שגיאות נרשמות (`logger.warning`+), לא נבלעות ב-`except: pass`.

### B5 · שינוי trading-logic
flag-gated · single-source-of-truth · smallest-correct-change · **strategic-stop + אישור Michael לפני הדלקה ל-live**.

### B6 · נאמנות להיקף
לבצע **בדיוק** את ה-phases הרשומים. אם phase חושף צורך נוסף — **לעצור ולדווח**, לא להרחיב בשקט.

## C · תבנית דוח חובה (כל דוח CC)
1. **טבלת phases:** `Phase · Status (DONE/PARTIAL/NOT-DONE) · Evidence (command+output) · Deviation/why`.
2. לכל טסט: שורת *"if reverted → RED because ___"*.
3. סעיף **NOT DONE / DEVIATIONS** (גם אם ריק — לכתוב "none").
4. **Open / מה נשאר.**

## D · אימות Cowork אחרי CC (לפני "בוצע")
Cowork בודק בלתי-תלוי: (1) האם הטסט **קורא לקוד האמיתי** (לא העתק)? (2) האם מבחן הליטמוס "revert→RED" מתקיים? (3) האם יש סעיף NOT-DONE? (4) הצלבת טענות מול code/git/DB. רק אז מסמנים DONE ב-STATUS_BOARD.
