## §0 · השאילתות שמייצרות את המספרים (להריץ לפני שמאמינים לי)

```sql
-- RR ונקודת-האיזון
SELECT mode, count(*) n,
  round(100.0*sum((pnl_usd>0)::int)/count(*),1) win_pct,
  round(avg(pnl_usd) FILTER (WHERE pnl_usd>0)::numeric,2) avg_win,
  round(avg(pnl_usd) FILTER (WHERE pnl_usd<0)::numeric,2) avg_loss
FROM v9_trades WHERE exit_price IS NOT NULL AND pnl_usd IS NOT NULL
  AND entry_ts>='2026-07-01' GROUP BY 1;

-- הדלי היחיד שמרוויח
SELECT CASE WHEN abs(entry_price-exit_price)<3 THEN '<3' WHEN abs(entry_price-exit_price)<5
            THEN '3-5' WHEN abs(entry_price-exit_price)<8 THEN '5-8' ELSE '8+' END d,
       count(*) n, round(100.0*sum((pnl_usd>0)::int)/count(*),0) win_pct,
       round(avg(pnl_usd)::numeric,2) avg
FROM v9_trades WHERE exit_reason IN ('STOP_HIT','STOP_FILL') AND exit_price IS NOT NULL
  AND entry_ts>='2026-07-01' GROUP BY 1 ORDER BY 1;
```

## 1א · `exit_fills` + MAE/MFE גם על עסקאות-צל

**הפער:** ‏`quality.exit_fills` קיים ב-**12 עסקאות** מתוך 413 — כולן לייב.
‏334 עסקאות-צל **אין בהן שום נתון-יציאה**. ⇒ אי-אפשר לדעת אם צל נגע ב-T1.

**‏🔴 מלכודת שאני נפלתי בה היום ותיעדתי:** שאילתה על `exit_fills LIKE '%T1%'` מחזירה
*"‏T1 נפגע ב-3% מהעסקאות"* — **וזה שקר**. זה מודד *"השדה מאוכלס"* ולא *"‏T1 נפגע"*.
**כל שאילתה על השדה חייבת לסנן `IS NOT NULL` תחילה** ולדווח את גודל-הבסיס.

**לבנות:** אותו רישום-יציאות שיש ללייב, גם על צל — `kind` (T1/T2/T3/STOP/SCRATCH),
`price`, `qty`, `ts`. בנוסף `quality.mae_pts` ו-`quality.mfe_pts` על **כל** עסקה סגורה.

**אימות דו-כיווני:** עסקת-צל שנגעה ב-T1 ⇒ `exit_fills` מכיל `T1` **ו-`mfe_pts ≥ מרחק-T1`**;
עסקה שהלכה ישר לסטופ ⇒ `exit_fills` = STOP בלבד ו-`mae_pts ≥ מרחק-הסטופ`.
**וטסט שנכשל אם השדה חוזר להיות `None` על צל.**
